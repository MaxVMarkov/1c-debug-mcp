# probes

Воспроизводимые пробы к серверу отладки. Все скрипты пишут журнал в `../evidence/`
(каталог в `.gitignore`), учётные данные берут только из окружения.

Общие переменные окружения:

| Переменная | Зачем |
|---|---|
| `V8_DB_USER` / `V8_DB_PASS` | учётные данные ИБ для HTTP/SOAP-вызовов опубликованной базы |
| `V8_BASE` | строка соединения для запуска клиента (`localhost/demo-base`) |
| `V8_CLIENT_EXE` | путь к `1cv8c.exe`, если не стандартный |
| `V8_CONFIG_SRC` | каталог XML-выгрузки конфигурации (для точек по имени модуля) |
| `DEBUGGER_URL` | адрес сервера отладки для `/DebuggerURL` (по умолчанию `http://127.0.0.1:15999`) |

| Скрипт | Что делает |
|---|---|
| `run_debug_session.ps1` | запускает тонкий клиент с `/DEBUG`, пароль в командную строку не попадает |
| `with_v8creds.ps1` | запускает команду с учётными данными из `HKCU\Environment` |
| `http_target_watch.py` | появляется ли цель у сеанса без `/DEBUG` (OData/HTTP-сервис) |
| `job_target_watcher.py` | пассивно наблюдает цели `JOB`: когда появляются и под каким именем |
| `rte_stop_probe.py` | останов по ран-тайм ошибке и идентификатор модуля из кадра |
| `headless_rte_stop.py` | авто-присоединение + `setBreakOnRTE` + один SOAP-вызов |
| `headless_acceptance.py` | тот же цикл, но через инструменты `mcp_core` (как в плагине) |
| `headless_bp_from_oracle.py` | версия модуля из кадра останова → обычная точка |
| `fire_ws_trigger.py` | выстрел по веб-сервису опубликованной базы (безголовый триггер) |
| `property_id_table.py` | эмпирическая таблица `propertyID` по профилям конфигуратора |
| `scan_property_guids.py` | поиск GUID свойств в бинарниках платформы |
| `extract_property_table.py` | таблица «имя свойства → GUID» из DLL поставки |
| `bodies/` | готовые SOAP-тела для триггеров |

Пробы рассчитаны на стенд, где кластер запущен с `-debug` и база опубликована.
